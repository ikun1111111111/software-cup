# 数字人声线试听优化设计

## 背景

数字人管理页当前提供“标准女声、年轻女声、东北女声”三个试听选项。现有实现将完整欢迎语发送至 `/api/tts/cache`，后端再调用实时 TTS。Redis 不可用或缓存未命中时，每次试听都可能重新合成；后端不可用时，前端又会退化为浏览器找到的同一个中文声音，导致三个选项播放缓慢且听感相近。

用户已在可视化方案中确认采用方案 A：预生成固定短试听音频。

## 目标

- 点击试听后立即给出播放反馈，在本地开发和常规网络环境下 300ms 内开始播放。
- 三个选项使用真实且不同的声音文件，不因后端、Redis 或外部 TTS 网络不可用而退化为同一声音。
- 通过文案标签明确表达三种声线的音色、节奏和口音差异。
- 正式数字人讲解仍使用已保存的 `voiceId` 和现有实时 TTS 流程，不改变生产讲解行为。

## 非目标

- 不修改聊天、导览或数字人口型同步的实时 TTS 流程。
- 不在本次工作中修复 Redis 服务或调整全局 TTS 缓存策略。
- 不让试听音频朗读用户当前编辑的完整欢迎语。

## 方案设计

### 静态试听资产

在 `frontend/public/audio/voice-previews/` 放置三段预生成 MP3：

| 声线 ID | 文件 | 后端声音 | 生成参数 | 展示标签 |
| --- | --- | --- | --- | --- |
| `mandarin` | `mandarin.mp3` | `zh-CN-XiaoxiaoNeural` | 语速 `-5%`，音高 `+0Hz` | 温柔清晰 · 稳重 · 标准普通话 |
| `female` | `female.mp3` | `zh-CN-XiaoyiNeural` | 语速 `+8%`，音高 `+6Hz` | 青春明亮 · 轻快 · 更有活力 |
| `liaoning` | `liaoning.mp3` | `zh-CN-liaoning-XiaobeiNeural` | 语速 `+0%`，音高 `-2Hz` | 亲切爽朗 · 地域感 · 更有记忆点 |

三段音频使用同一句短文案，以便用户比较声音本身：

> 你好，欢迎来到灵山景区，我是你的数字导游。

生成时使用表格中的固定语速和音高参数，以强化各声线既有特征，同时避免夸张变声效果。

### 前端数据模型

扩展 `AvatarPage` 的声线选项配置，为每个选项增加：

- `description`：可感知的声线说明。
- `previewUrl`：对应静态 MP3 地址。

试听不再调用 `previewVoice()` 或 `/api/tts/cache`，而是直接播放 `previewUrl`。

### 播放交互

1. 页面加载后预加载三段短音频。
2. 点击某个播放按钮时，立即停止并重置上一段音频。
3. 播放当前选项，并将按钮切换为明确的播放中状态。
4. 再次点击当前按钮可停止播放。
5. 音频播放结束或失败时恢复按钮状态。
6. 组件卸载时停止音频并释放事件监听。

声线卡片仍负责选择 `voiceId`；播放按钮只负责试听，避免试听动作意外改变已选配置。

### 视觉层级

每个卡片展示：

- 第一行：声音名称，例如“年轻女声”。
- 第二行：差异标签，例如“青春明亮 · 轻快”。
- 右侧：播放/停止按钮。
- 选中状态继续沿用现有朱红色边框和浅色背景。
- 播放中状态使用动态图标或“播放中”辅助文本，与选中状态相互独立。

### 错误处理

- 静态音频加载失败时显示“试听音频加载失败，请检查静态资源”，不再退化为同一个浏览器中文声音。
- 一个音频失败不影响其他声线试听和 `voiceId` 选择。
- 正式保存配置和正式讲解 TTS 流程保持不变。

## 数据流

```text
用户点击试听
  -> 根据 voiceId 读取 previewUrl
  -> 停止上一段 Audio
  -> 播放静态 MP3
  -> 更新 playingVoiceId
  -> ended/error 时清理状态
```

该流程不经过 FastAPI、Redis 或 Edge TTS 网络请求。

## 测试策略

- 单元测试：三个声线配置均包含不同的静态试听 URL 和清晰的差异标签。
- 单元测试：点击试听使用静态资源，不调用 `previewVoice()`。
- 单元测试：开始新试听时停止上一段音频。
- 单元测试：播放结束、失败和组件卸载时正确清理状态。
- 资产测试：三个 MP3 文件存在、非空且具有有效 MP3 文件头。
- 页面验证：三个卡片可选择，试听按钮不会改变选择状态，播放状态清晰可见。

## 验收标准

- 三个试听按钮不再请求 `/api/tts/cache`。
- 在正常本地开发环境中，点击后 300ms 内开始播放。
- 三个 MP3 分别由配置对应的三种声音生成。
- 用户无需只靠听感即可从标签理解声音差异。
- 后端或 Redis 停止时，三个试听仍可使用。
- 原有 `voiceId` 保存和正式讲解逻辑不受影响。
