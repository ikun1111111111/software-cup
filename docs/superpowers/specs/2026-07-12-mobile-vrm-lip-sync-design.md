# 移动端 VRM 自然口型设计

## 背景

移动端数字人说话时虽然 `mouthOpen` 数值会变化，但渲染层只驱动 VRM 的 `aa` 表情，因此视觉效果接近持续张嘴，缺少嘴唇收圆、横向展开和短暂停顿等细节。

## 目标

- 说话时在 `aa`、`ih`、`ou`、`ee`、`oh` 五种 VRM 口型之间连续变化。
- 保留现有 `mouthOpen` 作为整体开合强度，不改动 TTS 播放和字幕同步链路。
- 语音短暂停顿时允许嘴巴接近闭合；停止说话时立即清除口型残留。
- 使用逐帧确定性计算，不新增音频分析、网络请求或高频 React 状态更新。

## 不在本次范围

- 不实现中文音素到精确 viseme 的逐字映射。
- 不修改后端 TTS 返回格式。
- 不调整数字人的声音、字幕、表情或肢体动作。

## 方案比较

1. **仅调快 `aa` 开合**：改动最少，但仍然只有一种嘴型，无法解决“没有细节”。
2. **程序化多口型混合（采用）**：根据播放时间在五种口型间平滑切换，并由现有 `mouthOpen` 控制强度；性能开销低，所有移动端语音模式都可用。
3. **实时音频/完整音素驱动**：准确度更高，但需要扩展原生音频分析或 TTS 数据协议，超出本次小改动范围。

## 设计

### 口型计算

在 VRM 动画模块中增加一个纯函数，输入：

- 当前嘴部开合强度 `mouthOpen`，范围 `0..1`；
- 动画经过时间 `elapsed`；
- 是否正在说话 `speaking`。

输出五个口型权重。函数使用短周期、非完全等长的口型序列，让张嘴、扁嘴、圆唇交替出现；相邻口型通过插值过渡，避免逐帧跳变。整体权重乘以 `mouthOpen`，并设置上限，防止表情夸张。

### 渲染接入

`VRMView` 在 Web 与 Native 两条渲染循环中，将已有的 `elapsed` 和 `speaking` 一并传给嘴部应用函数。嘴部应用函数每帧设置五个 VRM 表情权重，不触发 React 重渲染。

停止说话时沿用现有重置入口，并将五个口型全部清零。非说话状态不持续覆盖普通面部表情，避免影响 `surprised` 使用的 `oh` 权重。

### 数据流

`TTS/浏览器语音 -> useVRMSync mouthOpen -> VRMView render loop -> 多口型权重 -> VRM expressionManager`

现有有音素数据时，`mouthOpen` 继续反映音素强弱；没有音素时，继续使用当前模拟强度。两种情况都由渲染层补充口型细节。

### 边界与降级

- `speaking=false` 或强度接近零时，输出闭嘴状态。
- 输入超出 `0..1` 时进行裁剪。
- 某个 VRM 模型缺少个别口型时，`expressionManager` 保持现有安全调用行为，其余口型仍可工作。
- 停止、切页或模型重载时清除平滑状态，避免下一次说话继承旧嘴型。

## 测试与验收

- 纯函数测试：静音输出全零，输入被裁剪，连续时间点会产生不同主口型，权重始终在合法范围内。
- 应用测试：说话时会写入多个口型，停止时五个口型全部归零。
- 回归验证：运行移动端相关 Jest 测试、TypeScript 检查和生产构建。
- 人工验收：连续说话时嘴型可见变化，不再保持单一张嘴；停顿和结束时能闭嘴。
