# 移动端数字人表演同步

## 2026-07-11

文字、语音、表情和动作统一以“音频实际开始播放”为时间零点：

1. `VRMManager.speak` 只登记本次文本、动作和目标 driver，不提前启动动作。
2. 浏览器 TTS 的 `onstart`、音频播放器的 `isPlaying` 或静音 fallback 开始后，发送带 `targetId` 的 `resync` 事件。
3. `useDigitalHumanDriver` 收到属于自己的 `resync` 后，只启动一次 `ExpressionPlayer`。
4. `ExpressionPlayer` 立即发送第一个时间轴事件，之后只在事件索引变化时更新。
5. 连续事件动作名称相同时只更新表情和时长，不通过 `none` 强制重播 GLB。
6. 页面气泡显示当前 `subtitle`，不再用完整 `speechText` 覆盖实时字幕；字幕边界不增加人工延迟。
7. 一次完整语音只选择一个主动作；逗号和句号分段只更新表情，不重新规划或重播 GLB。
8. 语音结束释放 React 动作状态时，已经启动的非待机 GLB 会按片段原始时长自然播放完成；新动作或明确打断仍可立即抢占。

相关回归测试覆盖：可听播放起点、driver 目标隔离、首动作单次触发、相同动作不重播、实时字幕优先级和语音边界同步。

## 2026-07-12

- 页面数字人恢复常驻文字气泡：待机时显示固定提示，TTS 加载和播放时优先显示当前 `subtitle` / `speechText`。
- 文字在 TTS 请求开始后立即可见，口型、表情时间轴和 GLB 动作仍以真实音频开始为时间零点。
- Web 端优先等待后端 TTS 真实音频，12 秒后才降级为浏览器语音，避免 Edge TTS 尚在合成时误播系统声。
- TTS Redis 读写的单次等待上限为 250ms，Redis 不可用时立即继续合成；进程内保留 128 条音频缓存。
- Expo 音频播放使用解码器提供的 `durationMillis` 作为真实时长，不再仅依赖后端 MP3 估算。
- 所有播放结束回调和兜底定时器绑定当前 `runId`；旧语音的延迟回调不能停止新语音。
- 真实音频播放结束回调为主停止信号，看门定时器使用解码时长加 5 秒容错，避免将长语音中途截断。
- 小灵默认 TTS 音色调整为 `female / zh-CN-XiaoyiNeural`，Edge TTS 使用 `rate=-4%`、`pitch=+2Hz`，降低播音腔并增加年轻感。
- Web 语音降级使用 `rate=0.94`、`pitch=1.02`，并按晓伊、晓晓等微软自然中文女声的顺序选择，不使用随机系统默认声音。
- `/chat` 与首页、景点、路线、地图、历史、记忆和个人页统一默认使用后端 `tts`；聊天页语音模式存储升级为 `@vrm_voice_mode_v2`，不再恢复旧版 Web `browser` 默认值。
