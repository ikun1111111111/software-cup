# 移动端景点探索页数字人主导重构计划

> 日期：2026-06-22  
> 范围：`software/mobile/app/(tabs)/explore.tsx` 为主，少量调整全局 VRM 浮窗策略  
> 核心目标：把“景点探索”从功能菜单页升级为“小灵主动导览”的移动端主入口

## 设计定位

当前探索页已有地图、拍照识景、扫码打卡、协同导览、路线和精选景点，但视觉重心仍像功能集合。改版后，用户进入页面首先看到的是数字人导览员“小灵”，由小灵解释当前可做什么，并引导用户开始路线导览、自由探索、识景或问询。

## 用户体验目标

1. 第一眼知道这是“数字人导游系统”，不是普通景区 App。
2. 小灵成为页面主角，地图与景点卡片服务于导览流程。
3. 用户可以快速进入三种核心路径：开始导览、自由逛、问小灵。
4. 保留现有能力入口：拍照识景、扫码打卡、路线选择、协同导览。
5. 不破坏已有 TourContext、VRMManager、地图、相机和扫码逻辑。

## 信息架构

### 1. 小灵导览舞台

- 页面首屏使用舞台式布局。
- 中央展示页面内 `VRMView`，让小灵成为视觉主角。
- 背景使用灵山实景图、墨色遮罩和柔和山水层次。
- 文案强调“小灵带你游灵山”。
- 行动入口：
  - `开始小灵导览`
  - `自由探索`
  - `问小灵`

### 2. 导览中控卡

- 当已有导览路线时，显示当前路线、进度、下一站。
- 当没有路线时，显示小灵推荐的默认路线或今日建议。
- 操作入口包括继续、暂停、地图和结束。

### 3. 小灵能力入口

原来的工具条重命名并视觉化为“小灵能做什么”：

- 识景：让小灵识别眼前景点。
- 打卡：让小灵确认到达。
- 路线：让小灵安排游览。
- 问询：和小灵聊一聊。

### 4. 陪伴式地图

- 地图不再作为第一视觉中心。
- 作为“小灵正在带你去哪里”的辅助模块。
- 点选景点后，小灵先播报一句，再显示故事卡和详情入口。

### 5. 小灵推荐故事流

- 原“精选景点”改成“小灵今天推荐”。
- 卡片文案从景点描述改成导览建议。
- 每张卡保留图片、类别、停留时间和最佳时段。

## 技术实施计划

### 阶段一：计划与结构收口

- 新增本计划文档。
- 确认探索页现有组件和全局 VRM 浮窗策略。
- 将探索页从“全局浮窗主导”调整为“页面内 VRM 舞台主导”。

### 阶段二：探索页首屏改版

- 在 `explore.tsx` 引入 `VRMView` 与 `useDigitalHumanDriver`。
- 将 `ExploreHero` 改造成 `GuideHeroStage`。
- 首屏渲染小灵、导览气泡、路线状态、三枚核心行动按钮。
- 页面初始化时由小灵主动欢迎。

### 阶段三：模块文案与视觉统一

- 将 `DiscoveryCommandDock` 改成小灵能力入口。
- 将地图模块文案改成陪伴式导览语气。
- 将精选故事流标题改成“小灵今天推荐”。
- 补齐此前新组件使用到但未定义的样式。

### 阶段四：浮窗避让

- 更新 `VRMProvider`，探索页使用页面内数字人舞台时隐藏右下角全局浮窗。
- 避免同一页面出现两个小灵。

### 阶段五：验证

- 运行 `cd software/mobile && npx tsc --noEmit`。
- 运行相关单元测试或全量 `npm test -- --runInBand`。
- 启动 Expo Web 预览，检查探索页首屏、地图、按钮和数字人层级。

## 验收标准

- 进入探索页第一屏，小灵占据主视觉中心。
- 页面仍能加载景点与路线数据。
- 拍照识景、扫码打卡、路线入口、问询入口仍可点击。
- 地图点选景点后仍能触发小灵播报并进入详情。
- TypeScript 检查通过。
