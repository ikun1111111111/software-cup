## 3. 真机验收前置条件

任选一种方式：

- Android 真机：安装 Expo Go，手机与电脑处于同一局域网。
- Android 模拟器：安装 Android Studio，并确保 `adb` 和 `emulator` 可用。
- iOS 真机：安装 Expo Go，手机与电脑处于同一局域网。

启动命令：

```bash
cd software/mobile
npm run start -- --host lan
```

验收前建议：

- 打开手机定位权限。
- 打开相机权限。
- 保持网络稳定。
- 如果后端服务未启动，聊天页应能走本地知识兜底。

## 4. 真机验收用例

### 用例 A：启动与基础页面

步骤：

1. 用 Expo Go 扫码打开应用。
2. 进入首页。
3. 切换底部 Tab：主页、探索、问答、记忆。

通过标准：

- 应用无白屏、无崩溃。
- 页面切换流畅。
- 中文文案显示正常。
- 顶部/底部安全区没有遮挡。

### 用例 B：主动导览闭环

步骤：

1. 首页点击主动导览，打开导览方案弹窗。
2. 选择单人导览并选择一条路线。
3. 观察是否进入第一个目标景点。
4. 在景点详情页执行打卡。
5. 点击继续导览。
6. 重复直到最后一个景点完成。

通过标准：

- 后端路线详情失败时，方案弹窗仍能显示本地或演示路线，不出现空白。
- `currentSpot` 对应当前目标景点。
- 完成 A 后进入 B，不跳过 B 直接去 C。
- 最后一站完成后导览结束。
- 导览进度、目标景点和页面跳转一致。

### 用例 B2：协同导览共享路线

步骤：

1. 进入探索页的协同导览卡片。
2. 创建房间，记录 6 位房间号。
3. 选择一条共享游览路线。
4. 使用另一台设备或另一个客户端加入同一房间。
5. 观察成员端是否显示同一条共享路线。
6. 两端分别点击“跟随此路线导览”。

通过标准：

- 房间显示成员数量和实时同步状态。
- 成员端加入后能恢复 `active_route`。
- 两端路线名称、站点顺序与游览路线详情一致。
- 点击跟随后，主动导览的当前站点为共享路线第一站。
- 手动添加景点或视觉识别同步不影响 `active_route` 的路线顺序。

### 用例 C：地图导航与 GPS

步骤：

1. 开始导览后进入地图页。
2. 允许定位权限。
3. 观察目标景点、距离提示和导航遮罩。
4. 保持页面一段时间，观察语音提示。

通过标准：

- 地图能显示当前位置。
- 导览目标优先使用当前目标景点。
- 距离刷新不会反复播放同一条导航语音。
- 点击到达或进入景点详情后流程能继续。

### 用例 D：数字人讲解

步骤：

1. 进入任一景点详情页。
2. 触发景点讲解。
3. 在聊天页询问灵山胜境相关问题。

通过标准：

- 数字人能播放讲解。
- 字幕、表情、动作、口型状态基本同步。
- 本地知识命中时，聊天气泡显示来源，数字人只播报答案正文。

### 用例 E：拍照打卡

步骤：

1. 在景点详情页选择拍照打卡。
2. 允许相机权限。
3. 拍摄照片并返回。

通过标准：

- 能正常打开相机。
- 拍照后无崩溃。
- 打卡流程能回到导览状态。

### 用例 F：扫码打卡

步骤：

1. 在景点详情页选择扫码打卡。
2. 允许相机权限。
3. 扫描包含景点 ID 或景点名的二维码。

通过标准：

- 能打开扫码界面。
- 二维码识别后能匹配景点。
- 扫码完成后导览状态不丢失。

### 用例 G：离线/后端异常兜底

步骤：

1. 不启动后端服务或断开后端地址。
2. 进入聊天页询问高频问题，例如“半日游怎么走”“九龙灌浴什么时候看”。

通过标准：

- 页面不崩溃。
- 本地知识库能返回可读答案。
- 答案展示来源。
