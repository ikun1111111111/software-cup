# 移动端景区导览与路线导览改造计划

## 背景

当前移动端“景区导览”页面只显示 5 个景点，原因不是灵山胜境只有 5 个地点，而是移动端演示数据 `localDemoData.ts` 只维护了 5 条景点兜底数据。后端结构化资料中已经整理了 19 个景点，移动端还同时存在 `localDemoData.ts`、`lingshanGuideData.ts`、`spot-locations.ts` 等多份景点/路线数据，导致地图、路线和数字人导览容易出现数量、坐标、名称不一致。

## 改造目标

1. 移动端离线/演示模式完整覆盖 19 个灵山胜境景点。
2. 景点名称、分类、坐标、简介、关联景点只维护一份移动端统一数据源。
3. “景区导览”和“路线导览”职责分清，减少页面重复。
4. 路线中的景点必须引用统一景点 ID，避免路线可见但地图不可导航。

## 数据定义

新增统一景点数据源：

`software/mobile/data/lingshanSpots.ts`

核心字段：

- `id`：稳定景点 ID
- `name`：中文名称
- `category`：核心景点、特色景点、文化设施
- `tags`：导览标签
- `overview`：列表和地图卡片摘要
- `detail`：详情页兜底讲解
- `latitude` / `longitude`：地图和导航坐标
- `qr_code`：扫码识别码
- `related_spots`：关联景点 ID

## 页面职责

### 景区导览

入口：`software/mobile/app/map.tsx`

职责：

- 展示灵山 19 个景点的全景地图。
- 支持自由点选、查看简介、导航到这里、进入景点详情。
- 当前存在路线导览时，只负责高亮当前路线/下一站，不重新管理路线流程。

### 路线导览

入口：

- `software/mobile/app/routes/index.tsx`
- `software/mobile/app/routes/[id].tsx`

职责：

- 展示精选路线。
- 开始、继续、暂停、结束数字人导览。
- 展示路线顺序、当前进度和下一站。
- 路线点位全部来自统一景点数据源。

### 探索页

入口：`software/mobile/app/(tabs)/explore.tsx`

职责：

- 作为导览主控台，保留“开始小灵导览”“自由探索”“问小灵”“协同导览”等入口。
- 不重复承载完整景点列表和路线详情。

## 实施阶段

### P0 统一景点数据（已完成）

- 新增 `lingshanSpots.ts`，录入 19 个景点。
- `localDemoData.ts` 改为从统一数据源读取景点。
- `spot-locations.ts` 改为从统一数据源派生坐标。

### P1 路线数据一致性（已完成）

- 本地演示路线引用统一景点 ID。
- 历史文化线、自然观景线、亲子互动线补齐真实路线节点。
- 测试所有路线景点 ID 都能在统一景点表中找到。

### P2 页面降重（已完成）

- 新增 `lingshanRoutes.ts` 作为统一路线源，探索页、路线页、离线兜底和 mock API 共享同一组路线顺序。
- 地图页聚焦全景自由探索，并在存在当前导览路线时高亮路线点位和当前站。
- 路线页保留路线选择、路线详情和导览进度职责。
- 探索页采用“主控优先”：保留 Hero、当前导览状态卡、识景/扫码、协同导览和后台工具入口，不再内嵌完整地图面板。

### P3 验证（已完成）

- 单元测试覆盖景点数量、唯一 ID、路线引用完整性、坐标覆盖。
- 单元测试覆盖统一路线源、mock API、默认导览路线和本地演示路线的一致性。
- 类型检查覆盖新增地图高亮 props、统一路线数据和导览数据派生。
- 手动验收重点：地图页显示“共 19 个景点”；探索页不再承载完整地图；从探索页或路线详情开始导览后，地图可区分当前路线点位和当前站。

## 当前执行范围

本轮完成 P0-P3。后续如继续优化，可进一步删除探索页中已不再渲染的旧预览组件代码和样式，或为地图高亮增加路线连线。
