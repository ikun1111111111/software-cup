# 移动端 AI 数字人导游演示脚本

> 对应方案：`docs/mobile-ai-digital-human-guide-plan.md`  
> 目标时长：3-5 分钟  
> 演示端：`software/mobile/`  
> 核心目标：证明数字人能完成“规划、导览、讲解、问答、记录、反馈”的游客闭环。

---

## 1. 演示前准备

### 1.1 服务状态

| 项目 | 要求 |
|---|---|
| 移动端 | `cd software/mobile && npm run start`，真机或 Web 预览可打开 |
| 后端 | FastAPI 服务可访问，聊天、导览、TTS 接口可用 |
| 网络 | 优先真实接口；现场不稳定时切换演示模式 |
| 数据 | 灵山胜境景点、路线、FAQ、讲解词已加载 |

### 1.2 演示模式兜底

需要预置以下内容：

1. 2 条路线：经典一小时、佛教文化深度游。
2. 5 个景点：灵山大佛、梵宫、九龙灌浴、五印坛城、拈花湾。
3. 10 条高频 FAQ：高度、开放时间、门票、路线、交通、历史、拍照点、亲子游、老人游、餐饮。
4. 3 段讲解词：欢迎词、灵山大佛讲解、梵宫讲解。
5. 1 条完整旅行记忆样例。

---

## 2. 推荐演示流程

### 0:00-0:30 开场：数字人欢迎

操作：

1. 打开 App 首页。
2. 数字人“小灵”出现，播放欢迎语。
3. 展示路线推荐入口。

推荐讲解词：

> 欢迎来到灵山胜境，我是你的 AI 数字人导游小灵。你可以告诉我游览时间和兴趣，我会为你规划路线、讲解景点，也可以随时回答问题。

评委看到的能力：

1. 数字人形象展示。
2. 语音播报、字幕、口型和表情联动。
3. 主动导览入口，而不是被动聊天机器人。

### 0:30-1:15 个性化路线：游客偏好输入

操作：

1. 在首页或聊天输入：“我只有一小时，想看最经典的景点。”
2. 数字人返回路线推荐。
3. 点击“开始导览”。

期望回答：

> 我推荐“经典一小时路线”：灵山大佛 -> 九龙灌浴 -> 梵宫。路线强度适中，能覆盖最有代表性的佛教文化与建筑景观，全程约 60 分钟。

评委看到的能力：

1. 个性化路线规划。
2. 推荐理由可解释。
3. 数字人从问答自然转入导览状态。

### 1:15-2:00 地图导览：前往目标景点

操作：

1. 进入地图页。
2. 地图高亮目标景点“灵山大佛”。
3. 展示距离、预计步行时间、下一步提示。
4. 点击“模拟到达”或使用定位触发到达。

期望播报：

> 我们先前往灵山大佛。当前距离约 300 米，预计步行 4 分钟。到达后我会为你详细讲解。

评委看到的能力：

1. 导览状态机。
2. 地图与数字人联动。
3. GPS 不稳定时有手动到达兜底。

### 2:00-3:00 到点讲解：灵山大佛

操作：

1. 到达灵山大佛后，点击“开始讲解”。
2. 数字人讲解灵山大佛，高度、文化含义、参观建议。
3. 观察表情、动作、口型、字幕。

期望讲解词：

> 这里是灵山大佛，高 88 米，是无锡灵山胜境的核心景观。大佛依山而立，面向太湖，象征庄严、慈悲与智慧。站在这里可以感受到佛教文化与山水空间的结合。

评委看到的能力：

1. 本地知识库讲解。
2. 语音与口型同步。
3. “高 88 米”“宏伟壮观”等内容触发惊叹或抬头动作。

### 3:00-3:50 智能问答：追问历史文化

操作：

1. 用户追问：“灵山大佛为什么是 88 米？”
2. 数字人回答，并展示知识来源或来源提示。
3. 再问一个边界问题：“这里能不能看到故宫？”

期望回答：

> 88 米是灵山大佛的重要标志性高度，体现其庄严尺度，也方便游客从远处识别。根据灵山胜境资料，景区的核心讲解重点在佛教文化、太湖山水和建筑艺术。

边界问题期望：

> 资料中没有提到灵山胜境可以看到故宫。故宫位于北京，和无锡灵山胜境不在同一城市。

评委看到的能力：

1. RAG 知识问答。
2. 未知/不相关问题不编造。
3. 问答延迟目标小于 5 秒。

### 3:50-4:40 旅行记忆：行程总结

操作：

1. 完成当前景点，点击“结束导览”或“生成回顾”。
2. 进入记忆页。
3. 展示到访景点、问答次数、情绪标签、打卡印章。

期望内容：

> 今天你完成了经典一小时路线，重点参观灵山大佛，并咨询了佛教文化相关问题。小灵已为你生成一张灵山手帐，可以保存或分享。

评委看到的能力：

1. 游览行为沉淀。
2. AI 生成旅行记忆。
3. 游客体验从导览到回顾闭环。

### 4:40-5:00 管理端数据回流

操作：

1. 切到管理端或展示截图。
2. 展示问答热词、路线完成率、景点热度、知识库维护入口。

评委看到的能力：

1. 后台分析。
2. 知识库维护。
3. 景区运营闭环。

## 3. 演示问题清单

| 类型 | 问题 | 期望能力 |
|---|---|---|
| 路线 | 我只有一小时，怎么游览最合适？ | 个性化路线 |
| 景点 | 灵山大佛有多高？ | 知识库事实问答 |
| 文化 | 梵宫有什么特色？ | 文化讲解 |
| 交通 | 从当前位置怎么去梵宫？ | 地图导览 |
| 人群 | 带老人适合走哪条路线？ | 个性化推荐 |
| 边界 | 灵山大佛是不是在北京？ | 纠错与拒答 |
| 情感 | 谢谢你讲得很清楚 | 感谢表情/鞠躬 |
| 未知 | 这里今天某个摊位几点关门？ | 不编造 |

---

## 4. 现场风险处理

| 问题 | 处理 |
|---|---|
| TTS 播放失败 | 保持字幕和文字回答，说明语音服务可降级 |
| 定位失败 | 使用“模拟到达”按钮演示到点讲解 |
| 后端接口慢 | 使用演示模式预置问答 |
| VRM 白屏 | 切换 2D/静态数字人 fallback |
| 网络断开 | 展示本地路线、讲解词、记忆闭环 |
